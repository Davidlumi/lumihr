# §4 vacuity sweep — full classification

Every check in the sixteen-gate suite, classified by the quantifier that produces its
boolean. **Arm A** = existential predicate standing in for a per-instance property.
**Arm B** = universal predicate over a population that can legitimately be empty.

shape and is counted separately in the report). Classification is per-check reading of

## identity_recon.py — 12 checks

> SHAPE OF THE FILE. There is no check()/fail()/ok()/assert_ helper and no FAILS list. Verdicts are inline: three set-arithmetic counters (lines 120-122) and a per-pair `fatal` flag set by three classifier branches (161, 170, 177), all folded into a single module-level `ok` at line 191 and turned into exit 0/2 at line 198. Six distinct boolean gates, instantiated four times each by the PAIRS loop = 24 check instances, plus the rollup. I classified 12 entries: the 6 gates, the 2 per-table drift-narrowing instances that behave materially differently, the password_resets block, the in_progress guard, the rollup, and the declared sessions exclusion. ARM A: NONE. The file contains no text-scan or document-search idiom at all — no any(), no `x in text`, no re.search, no len(...) > 0 over a rendered surface. Every failure trigger is a fail-existential (`if partial:`, `if populated:`, `if empty:`), which is the CORRECT polarity: a fail-existential is logically identical to a pass-universal (not any == all not), so these are the safe direction and none of them substitutes for a per-instance requirement. The only Arm-A-SHAPED construct is line 162: one global scalar (MARKER['step5_state'] == 'in_progress') excuses a requirement that is genuinely per-column, suppressing the PARTIAL fatal across all four pairs at once. It fails the stated Arm A test only because the predicate is scalar rather than existential — flagged as `arm: none` but it is the one substitution worth a ruling. ARM B: EVERYTHING ELSE. All six gates are universals over populations that a valid organisation can empty. Three block-level emptiers dominate any single check: 1. THE FIFTH STATE, 'NO ROWS' (lines 92-93). The docstring advertises a four-world classifier (ABSENT/EMPTY/POPULATED/PARTIAL) and claims correctness "in all three worlds, without a flag to remember". classify() actually returns a fifth value, 'NO ROWS', on any zero-row table — and 'NO ROWS' matches NONE of the three buckets at lines 112, 158, 159. A table with no rows is therefore invisible to the PARTIAL detector, the marker-complete CONTRADICTION detector AND the marker-loss detector simultaneously. For most real orgs `password_resets` and often `invites` are empty, so three of the six gates are already dark on half the pairs. This is the single highest-value finding in the file: the state was introduced for a good reason (avoid dividing by an empty table) and then omitted from every downstream bucket. 2. THE MARKER IS None TODAY, SO TWO GATES ARE DEAD ON EVERY CURRENT RUN. identity.step5_marker() returns None when identity.db has no `meta` table or no id=1 row (identity.py:154-158), and set_step5_marker's writer is deliberately unbuilt ("commits 5/6", identity.py:163-167). So `state` is None on every run today: the CONTRADICTION check (line 170, guarded `state == "complete"`) never executes, and the NO-MARKER check (line 177) executes but finds `empty` == [] because the columns are still POPULATED. The gate prints "marker consistent" in its PASS line while the two marker gates have never been exercised against a real positive. 3. password_resets IS PERMANENTLY UNCLASSIFIED. STEP5_REMOVED["password_resets"] = () (line 70) makes `states` == {} for that pair forever, so all three classifier gates are unreachable for it by construction. The file's own comment (lines 62-65) admits the constant is an assumption because neither S6 step 5 nor DECISIONS enumerates the moved columns — meaning the population of three checks is set by a placeholder. THE DRIFT CHECK IS THE WEAKEST THING THE FILE ADVERTISES MOST. The docstring's headline claim ("Drift is FATAL", "strictly more than the old fixed set could detect") rests on a predicate that, post-step-5, compares ('org_id',) against ('org_id',) for the orgs pair — a tautology over a non-empty population, which is a third vacuity mode distinct from both arms and arguably worse than either, since it survives any amount of data. For users it thins to a single column (org_id). The script SELF-DISCLOSES this at lines 152-155 ("the drift check covers only the invariant columns above; membership is what it still proves") — but the disclosure is a print, not a downgrade: the gate still prints "PASS — ... 0 drift" and exits 0. A gate that knows it is measuring nothing and still reports a green scalar is the exact failure the P2 note at lines 12-20 was written to prevent, reproduced one layer down. ADJACENT SOUNDNESS HOLE (not vacuity, but it shrinks every population silently). Lines 116-119 build `rrows`/`irows` as dict comprehensions keyed by `key`. If a table holds duplicate key values, later rows silently overwrite earlier ones, so both orphan counts and the drift intersection are computed over a SMALLER population than the tables contain, with no row-count reconciliation against the raw COUNT(*). The printed "reward=%d identity=%d" figures are the deduplicated dict lengths, so the output cannot reveal the collapse either. WHAT IS ACTUALLY LOAD-BEARING TODAY. Of six gates × four pairs, the ones that can genuinely fail on a real org right now are the two orphan directions (universals with non-empty populations wherever the tables have rows) and the PARTIAL detector on orgs/users. Everything else is either dead on the current marker state, empty by construction, or tautological.
